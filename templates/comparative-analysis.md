# Comparative Analysis Template

A structured approach to comparing alternatives using Perplexity.

---

## Template

### Step 1: Define Comparison Scope
```
Compare: [ITEM A] vs [ITEM B] vs [ITEM C]

Context: [WHY YOU'RE COMPARING]
Focus areas: [SPECIFIC ASPECTS TO COMPARE]
Time frame: [RELEVANT TIME PERIOD]
```

### Step 2: Establish Comparison Dimensions
```
For [ITEMS], compare across these dimensions:

1. [DIMENSION 1] (e.g., Cost, Performance, Features)
2. [DIMENSION 2]
3. [DIMENSION 3]
4. [DIMENSION 4]
5. [DIMENSION 5]

For each dimension, provide:
- Specific data or evidence
- Source citations
- Date of information
```

### Step 3: Create Comparison Table
```
Create a comparison table:

| Dimension | [ITEM A] | [ITEM B] | [ITEM C] |
|-----------|----------|----------|----------|
| [DIM 1]   |          |          |          |
| [DIM 2]   |          |          |          |
| [DIM 3]   |          |          |          |

Cite sources for each cell.
Include dates for time-sensitive information.
```

### Step 4: Identify Unique Strengths
```
What is each option uniquely good at?

[ITEM A]: Best for [USE CASE] because [REASON]
[ITEM B]: Best for [USE CASE] because [REASON]
[ITEM C]: Best for [USE CASE] because [REASON]

Cite specific evidence for each claim.
```

### Step 5: Identify Trade-offs
```
What are the key trade-offs between these options?

- [ITEM A] vs [ITEM B]: [TRADE-OFF]
- [ITEM B] vs [ITEM C]: [TRADE-OFF]
- [ITEM A] vs [ITEM C]: [TRADE-OFF]

Explain when each trade-off matters.
```

### Step 6: Contextual Recommendations
```
Which option is best for:

- [SCENARIO 1]: [RECOMMENDATION] because [REASON]
- [SCENARIO 2]: [RECOMMENDATION] because [REASON]
- [SCENARIO 3]: [RECOMMENDATION] because [REASON]

Include caveats and confidence levels.
```

## Example: Comparing Cloud Providers

### Step 1: Scope
```
Compare: AWS vs Google Cloud vs Azure

Context: Choosing cloud provider for a startup building a SaaS product
Focus areas: Pricing, ease of use, AI/ML capabilities, startup programs
Time frame: Current (2024) offerings
```

### Step 2: Dimensions
```
Compare AWS, Google Cloud, and Azure across:

1. Pricing (compute, storage, data transfer)
2. Free tier and startup credits
3. AI/ML services and capabilities
4. Developer experience and learning curve
5. Market share and ecosystem
6. Support and documentation quality

For each, provide current pricing, feature lists, and user reviews.
Cite official documentation and recent comparisons.
```

### Step 3: Table
```
Create detailed comparison table with columns:
- Provider
- Compute pricing (per hour for standard instance)
- Free tier limits
- Startup program benefits
- Key AI/ML services
- Market share %
- G2 rating

Include citations and last-updated dates.
```

### Step 4: Unique Strengths
```
What is each provider uniquely good at?

AWS: [Find specific strengths - breadth of services, market maturity, etc.]
Google Cloud: [Find specific strengths - AI/ML, data analytics, etc.]
Azure: [Find specific strengths - Microsoft integration, hybrid cloud, etc.]

Cite analyst reports, user reviews, and technical comparisons.
```

### Step 5: Trade-offs
```
Key trade-offs:

- AWS vs Google Cloud: [Maturity/breadth vs innovation/pricing]
- Google Cloud vs Azure: [AI capabilities vs enterprise integration]
- AWS vs Azure: [Market leader vs Microsoft ecosystem]

For each, explain when the trade-off matters and for whom.
```

### Step 6: Recommendations
```
Best choice for:

- AI/ML-heavy startup: [RECOMMENDATION] because [EVIDENCE]
- Microsoft shop: [RECOMMENDATION] because [EVIDENCE]
- Cost-sensitive early stage: [RECOMMENDATION] because [EVIDENCE]
- Need broadest service catalog: [RECOMMENDATION] because [EVIDENCE]

Include confidence levels and caveats.
```

```
- [Key dimension 1]

- [Key dimension 3]

Present as table with citations.

Best for:
- [Use case 1]: [Choice] because [Reason]
- [Use case 2]: [Choice] because [Reason]
```

---

## Tips for Effective Comparisons

### ✅ DO:
- Define clear comparison dimensions upfront
- Use tables for easy scanning
- Cite all claims
- Consider multiple use cases
- Acknowledge trade-offs
- Note when information was last updated

### ❌ DON'T:
- Compare apples to oranges (ensure comparable)
- Use outdated information
- Ignore context (best for whom?)
- Present one-size-fits-all recommendations
- Forget to cite sources
- Over-simplify complex trade-offs
